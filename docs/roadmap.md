2. **导入与核对。** 从当前 CSV/JSON 导入开发库，保留来源、导入批次与稳定编号。先输出差异报告，再验证 21 个产品和各分支金额一致；包含导游、车辆、可选体验、零成本与冲突拦截。导入可重复运行，不重复创建数据；备份并记录回退办法。数据库成为主数据后，CSV 作为导入/导出与来源归档，不长期双写。
3. **后端切换。** 在数据访问层接入数据库，保持旅客 API 字段和成本 × 1.3 规则；整套验证通过后再切换读取来源。供应商联系方式、成本单价与运营记录不出现在公开接口。
4. **维护入口与权限。** 建立运营登录和受控的产品、成本、供应商维护页面，记录修改人和历史版本；对外正式发布前限制内部成本接口权限。数据库存储和维护页面一起才能改善日常维护。
5. **询单与报价记录。** 保存需求、所选分支、成本和销售规则版本、销售报价快照，后续改价不覆盖已发报价。历史付款存储 `data/payments.json` 单独审计和迁移，保持原文件及备份，不与旧付款资料自动合并。

本地备份恢复已验证，随后再完成生产备份策略、部署和正式访问配置。账户/订单/支付功能按实际业务需要确定，不随数据库迁移自动扩大平台范围。

### 推荐的运营模式（规划，尚未实施）

同一个产品系统提供两个入口：用户浏览 `/`、`/plan`；运营登录 `/ops` 后处理咨询与报价。两者共用 FastAPI 与 PostgreSQL，旅客看到公开产品/销售金额，运营看到咨询、内部成本与处理记录。无需另建独立产品库或让旅客进入旧 Streamlit 表单。

`/ops` 是待建设的入口，当前不存在。内部页面和接口都必须校验运营身份；隐藏链接不能代替权限。参考 [OWASP 授权指导](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。第一版以咨询列表和详情为范围，暂不扩展订单、支付、客户账户或完整在线聊天。

运营流程：

1. 旅客看完 02，点击 **Talk to a Travel Expert**，提交咨询。
2. 系统先保存咨询单与行程快照，成功后显示咨询编号。只有持久化成功才显示“已收到”；失败保留输入并允许重试，重复点击不重复创建咨询。
3. 运营在咨询列表看到新需求，领取或指派负责人；确认日期、人数、路线/体验、车辆、实际季节与导游可用性。
4. 运营通过业务邮件或 WhatsApp 联系客人，调整行程并生成新的报价版本；客户此前看到的估算与运营正式报价分别保留。
5. 记录已联系、方案已发送、已确认或暂不继续，附跟进时间与处理备注。客户沟通与供应商安排分开，供应商联系方式/成本不进入客户响应。

### 02 联系入口设计（2026-10-09 已实施）

以一个主要按钮为主，不增加多个聊天渠道选择器：

- 在 02 的行程与体验展示末尾放一个主要按钮 `Talk to a Travel Expert`，配短文案：`Let’s make this journey yours.`。不同时摆放多个渠道按钮，让客人读完产品后自然进入咨询。
- 点击后在 02 展开轻量联系表单，自动带入已预览的目的地、天数、日期、人数、分支、已选体验和包车选择。客人无需重复填写行程。
- 第一版只要求 **Name、Email**；`Message` 可选，原有备注一并带入。无需注册，不先收集护照、住址或付款信息。可提供联系用途说明，不默认订阅营销。
- 主要按钮为 `Send My Journey Enquiry`。成功显示 `We’ve received your enquiry.` 与咨询编号，不编造回复时限、在线客服状态或订单确认。
- 行程尚未生成时引导先预览；修改选择后需更新预览再提交，避免把旧结果当新选择发送。估算待确认或报价服务失败时仍允许提交咨询，明确记录金额未确认。
- WhatsApp 可作为后续次要联系渠道，需先配置真实业务号码；支持预填咨询编号和简短行程摘要，旅客还需发送消息。依据 [WhatsApp 官方说明](https://faq.whatsapp.com/5913398998672934)。跳转聊天本身不会自动创建本系统咨询单，也不代表团队已收到消息。

### 用户信息如何与运营表单关联

用**咨询编号/数据库关联**连接，而不是复制两套表单：

- 新增咨询记录：姓名、邮箱、可选留言、产品编号、旅客需求快照、来源页面、创建时间、状态和负责人。

- 客户页面仅返回咨询编号和确认信息，内部成本、联系人列表、运营备注与负责人权限留在运营接口。

当前 `quote_snapshots` 可以作为版本化报价基础，但没有客户身份/咨询状态字段，不能直接把它当成完整咨询表。已有 `travel_app` 只读，不应为了收咨询就改成能写全部表；新增受限写入权限处理咨询，维护权限单独保留。
