### 第一步：共享视觉与页面骨架

组件骨架已完成：顶部导航、页脚、字体/颜色/间距变量，以及 `/`、`/plan` 两个可独立访问的页面。供应商付款、内部审核和原始 JSON 留在运营流程。品牌“行旅”是界面暂用名称，可在正式文案阶段调整。

- 正文与输入框 16–18px，辅助说明 14px，分区标题 24–28px，首页标题桌面 48–56px、手机 32–36px。
- 暖白背景、深绿主色、少量沙色强调；内容最大宽度约 1200–1280px，8px 间距体系，按钮高度至少 44px。
- 首页使用目的地摄影和宽松留白；规划页提高信息密度，优先保证表单与每日行程的阅读。
- 第一版用中文完成页面，文案独立存放；面向入境游客的英文内容在发布前准备，不提前放空语言切换按钮。

验收：两页导航与直接访问正常；手机顶部导航可用；200% 放大后内容可读；键盘焦点清晰。

### 第二步：产品首页

页面从上到下：导航 → 目的地大图与双入口 → 热门目的地 → 旅行产品筛选与卡片 → 定制说明 → 页脚。主按钮为“探索行程”，次按钮为“定制我的旅程”；前者跳到本页产品区，后者进入 `/plan`。

交互组件已完成，正式产品内容待下一轮填充：产品卡片、目的地筛选、时长筛选，以及卡片进入定制页时预填样例/城市的行为。当前 `demo-*` 编号不能作为后端正式产品编号使用。

- 卡片展示图片、城市、产品名称、实际天数、2–3 个体验亮点、“预览这条行程”。桌面每行 3 张，平板 2 张，手机 1 张。
- 城市来源于产品库；首批覆盖已有产品的城市，不展示没有产品的虚构目的地。
- 由 CSV/规范化数据按字段白名单准备前端展示数据，保留稳定 `product_id`。照片、简介、主题标签为独立展示内容，不修改成本库。
- 图片使用可公开且授权明确的目的地素材；未取得素材时明确使用占位，不将占位图说成实景。
- 无筛选结果时提供“清除筛选”。不编造销量、评论、用户数量或低价承诺。
- 未建立销售价格时不展示“起价”；以行程与体验吸引浏览，实际报价另行确认。

验收：筛选组合、清空、空结果都可演示；产品名称/编号/天数与来源一致；点击产品能够携带选择进入 `/plan`。

### 第三步：行程定制与预览页

旅客表单、演示服务、结果快照与每日预览组件已完成；目前仅按样例城市与天数查找示意内容，不执行真实推荐或业务规则。先完成单城市产品流程，再单独确认多城市组合；当前简化全链路接口只有一个 `city`，不假设已经实现跨城市交通与完整拼接。

- 页面标题“设计你的中国旅程”。桌面左侧约 35% 需求、右侧约 65% 预览；手机按“填写 → 生成 → 查看”顺序上下排列。
- 表单分为目的地与日期/天数、成人/儿童/长者、兴趣与服务。自然语言需求放在可展开区域，不要求用户先写一封询单。
- 天数约束按接入接口校验；简化接口当前支持 1–10 天。日期、导游、包车与可选体验按现有字段映射。预算先留作后续需求，不能声称当前匹配会按预算筛选。
- 从首页产品进入时预填城市与产品天数，保留 `product_id`。若用户修改导致产品不再符合需求，提示重新匹配。
- 结果显示需求摘要、推荐产品与实际时长、每日时间线、已含/可选体验、待确认事项。填写的期望天数不直接替换产品真实天数。
- 成本不作为客户售价展示。预览阶段可用“报价待确认”；模拟产品与行程明确标注，不使用固定假价。
- 状态包括未生成、生成中、成功、无匹配、失败、输入已变更。生成后保留输入与结果快照；修改输入时标明旧方案待更新，再生成成功后替换。
- 保留直接输入与选择两种方式的能力；AI 原文抽取在后端联调阶段接入。先预览，无需注册；咨询提交在存储接口实现后开放。

验收：完整表单→生成→逐日预览→修改→重新生成流程；无匹配不返回无关城市；返回首页与刷新行为合理；浏览器前进/后退可用。
