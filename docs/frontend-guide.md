# 前端开发约定

## 本轮已明确的方向（2026-10-07）

最新方向：新网站采用旅客视角，首批为产品首页 `/` 与行程定制页 `/plan`。详细设计、实施顺序与验收条件统一维护在 [路线图](roadmap.md)。现有运营功能继续保留在旧界面，供应商付款、内部审核与原始 JSON 不出现在旅客网站导航。

- 用户流程为“浏览产品 → 选择产品或填写需求 → 预览每日行程 → 调整需求”。自然语言描述为可选补充。
- 采用顶部导航；规划页桌面约 35% 表单、65% 结果，窄屏上下排列。
- 正文/输入 16–18px、说明 14px。首页突出目的地摄影与产品，规划页突出表单与每日行程。
- 兴趣与可选体验展示可读名称，底层保留稳定产品/项目编号。
- 模拟数据明确标注；修改需求后标明方案待更新。成本不能充当客户销售报价。

创建时选择自定义设置，建议如下：

| 配置 | 选择 |
|---|---|
| 使用推荐默认配置 | No，选择 customize settings |
| TypeScript | No，延续 JavaScript/JSX |
| 代码检查 | ESLint |
| React Compiler | No |
| Tailwind CSS | No，使用普通 CSS |
| `src/` 目录 | No |
| App Router | Yes |
| Cache Components（如出现） | No，本轮暂不引入 |
| 自定义 import alias | No，保留 `@/*` |
| 生成 AGENTS.md | Yes，生成后补充本项目规则 |
| 匿名开发反馈（如出现） | No |

问题顺序以运行时版本为准。这是结合项目学习路线的选择，不是对所有 Next.js 项目的通用要求。选项已参考 [官方创建说明](https://nextjs.org/docs/app/api-reference/cli/create-next-app)。

项目顺序已调整为：目录整理 → 新前端页面 → 前后端联调与业务存储 → 上线。前端创建在当前仓库的 `frontend/` 中，保留已有后端与旧 Demo。

## 1. 已创建前端的启动方式

在本项目根目录执行：

```bash
cd frontend
npm run dev
```

`frontend/` 已完成创建和 animejs 安装，无需重复运行创建命令或 `git init`。首次拉取代码后先在 `frontend/` 执行 `npm ci`。

仓库路径包含冒号，会破坏 npm 放入 `PATH` 的本地 `.bin` 路径；当前脚本通过 Node 直接调用已安装的 Next.js/ESLint CLI。改启动脚本时保留这个兼容处理。

若延续学习项目的配置，可在创建时选择 JavaScript、ESLint、App Router、普通 CSS、不使用 `src/` 目录。创建工具的问题以实际显示为准；不通过记忆猜测最新版动画接口，开发时查看安装版本的文档。

浏览器打开开发服务器实际提示的地址。先确认默认页能显示、没有启动错误，再开始做业务页面。保持开发服务器运行，编辑页面时即时查看结果。

## 2. 先确定这一轮页面范围

完整网站定位仍可后续调整。首批两页先完成产品展示与旅客行程预览；上海半定制入口的呈现方式在该流程稳定后决定。

本阶段用明确标注的模拟数据完成界面，不依赖 LLM 和数据库。模拟数据与现有 Pydantic 结构对照，避免之后接接口时重做字段。

建议前端内部结构：

```text
frontend/
├── app/             # 页面和布局
├── components/      # 可复用界面
├── data/            # 模拟数据与静态页面内容
├── lib/             # 之后加入的 API 请求工具
├── css/             # 普通 CSS 与共享变量
└── public/          # 可以公开的素材
```

只在实际需要时创建目录，不把业务资料文件夹直接复制到 `public/`。

## 3. 开发时持续检查

- 页面导航、返回与刷新符合预期。
- 表单能输入、修改、校验，结果状态可以演示。
- 手机宽度布局可用；文字与报价明细能够阅读。
- 等待、无结果、错误等状态有清晰反馈。
- 组件和页面分开，共享样式与数据不反复复制。

共享业务 API Key 留在服务端；`NEXT_PUBLIC_*` 只能存可公开配置，不能存真实密钥。

## 4. 完成一个页面阶段后检查再继续

仍在 `frontend/` 执行：

```bash
npm run lint
npm run build
```

以创建出的 `package.json` 中实际脚本为准。构建通过之后，才能把这一阶段称为完成；本地热更新正常不等同于生产构建成功。

回到根目录查看变动：

```bash
cd ..
git status
```

目录整理与前端功能宜分别提交。当前已有用户变动和本次迁移，先检查再决定提交范围，不把 `.env`、`.venv/`、私人资料、依赖或构建目录加入 Git。

前端完成后，继续按 [路线图](roadmap.md) 接入接口、完善保存和权限，最后准备部署。
